# سجل أنشطة معالجة البيانات الشخصية

**الحالة:** مسوّدة تشغيلية — **تحتاج مراجعة قانونية قبل الإطلاق**  
**آخر تحديث:** 16 أغسطس 2026  
**المرجع:** قانون حماية البيانات الشخصية العُماني ولائحته التنفيذية —
[وزارة النقل والاتصالات وتقنية المعلومات](https://mtcit.gov.om/sectors/governance/personal)

> هذه الوثيقة تصف ما **ينفّذه النظام فعلياً اليوم**، لا ما هو مخطط.
> أي ميزة جديدة تعالج بيانات شخصية تُضاف هنا في نفس الـPull Request.

---

## 1. صفة المنصة

| الحالة                                   | الصفة                                    |
| ---------------------------------------- | ---------------------------------------- |
| بيانات حسابات المستخدمين                 | المنصة **مُتحكِّم**                      |
| بيانات جهات الاتصال التي تجمعها المؤسسات | المنصة **مُعالِج** والمؤسسة هي المتحكِّم |

التمييز مهم: طلبات صاحب البيانات المتعلقة بجهات الاتصال تُوجَّه إلى
المؤسسة صاحبة البطاقة لا إلى المنصة.

## 2. أنشطة المعالجة الحالية

### 2.1 إدارة الحسابات

| البند           | التفصيل                                                          |
| --------------- | ---------------------------------------------------------------- |
| الغرض           | تمكين المستخدم من الدخول وإدارة مؤسسته                           |
| الأساس القانوني | تنفيذ عقد الخدمة                                                 |
| البيانات        | البريد، الاسم، معرّف Auth0، اللغة، المنطقة الزمنية، وقت آخر دخول |
| المصدر          | المستخدم مباشرة عبر Auth0                                        |
| مدة الاحتفاظ    | حتى حذف الحساب                                                   |
| المستقبِلون     | Auth0 (مزوّد الهوية)                                             |

### 2.2 عضوية المؤسسات والصلاحيات

| البند           | التفصيل                                              |
| --------------- | ---------------------------------------------------- |
| الغرض           | تحديد صلاحيات الوصول                                 |
| الأساس القانوني | تنفيذ عقد الخدمة                                     |
| البيانات        | معرّف المستخدم، معرّف المؤسسة، الأدوار، حالة العضوية |
| مدة الاحتفاظ    | حتى حذف الحساب أو إلغاء العضوية                      |

### 2.3 سجل التدقيق

| البند           | التفصيل                                                  |
| --------------- | -------------------------------------------------------- |
| الغرض           | أمن المعلومات وإثبات العمليات ذات الأثر                  |
| الأساس القانوني | المصلحة المشروعة في أمن النظام                           |
| البيانات        | الفاعل، المؤسسة، العملية، المورد، الوقت، معرّف الطلب، IP |
| مدة الاحتفاظ    | **غير محددة بعد — قرار مطلوب**                           |
| ملاحظة          | يُصفَّر حقل الفاعل عند حذف الحساب فيبقى السجل بلا هوية   |

### 2.4 الموافقات

| البند           | التفصيل                                             |
| --------------- | --------------------------------------------------- |
| الغرض           | إثبات الموافقة وسحبها                               |
| الأساس القانوني | التزام قانوني                                       |
| البيانات        | الغرض، القرار، إصدار المستند، الوقت، IP، User-Agent |
| مدة الاحتفاظ    | حتى حذف الحساب                                      |

### 2.5 الملفات المرفوعة

| البند           | التفصيل                                    |
| --------------- | ------------------------------------------ |
| الغرض           | عرض الصور والشعارات والمستندات على البطاقة |
| الأساس القانوني | تنفيذ عقد الخدمة                           |
| البيانات        | صور شخصية وشعارات ومستندات يرفعها المستخدم |
| مدة الاحتفاظ    | حتى حذف الملف أو حذف الحساب                |
| موقع التخزين    | Object Storage متوافق مع S3                |

### 2.6 جهات الاتصال الملتقطة من النموذج العام

| البند               | التفصيل                                                                                 |
| ------------------- | --------------------------------------------------------------------------------------- |
| صفة المنصة          | **مُعالِج** — المؤسسة صاحبة البطاقة هي المتحكِّم                                        |
| الغرض               | تمكين صاحب البطاقة من التواصل مع من شارك بياناته معه                                    |
| الأساس القانوني     | **موافقة صريحة** من صاحب البيانات، مسجَّلة في `contact_consents`                        |
| البيانات            | الاسم، البريد، الهاتف، جهة العمل، المسمى، رسالة الزائر، حقول مخصصة يعرّفها صاحب البطاقة |
| المصدر              | صاحب البيانات مباشرة عبر النموذج العام، أو إدخال يدوي من المؤسسة                        |
| مدة الاحتفاظ        | حتى حذف المؤسسة لها أو حذف حسابها — **لا حذف تلقائي بعد**                               |
| المستقبِلون         | مزوّد البريد (رسالة الشكر وإشعار صاحب البطاقة)                                          |
| طلبات صاحب البيانات | تُوجَّه إلى المؤسسة صاحبة البطاقة لا إلى المنصة                                         |
| التفصيل             | [contacts/capture.md](../contacts/capture.md)                                           |

> الإدخال اليدوي (`source = manual`) **بلا صف موافقة**: الأساس القانوني
> فيه ليس موافقة مُنحت للمنصة، والمؤسسة مسؤولة عن سنده.

### 2.7 موافقات جهات الاتصال

| البند           | التفصيل                                                     |
| --------------- | ----------------------------------------------------------- |
| الغرض           | إثبات أن البيانات حُفظت بموافقة، وإثبات نص الموافقة وإصداره |
| الأساس القانوني | التزام قانوني                                               |
| البيانات        | الغرض، القرار، إصدار النص، المصدر، الوقت، IP، User-Agent    |
| مدة الاحتفاظ    | مربوطة بجهة الاتصال — ولهذا حذفها **ناعم** لا صلب           |

### 2.8 تحليلات البطاقات العامة

| البند             | التفصيل                                                                              |
| ----------------- | ------------------------------------------------------------------------------------ |
| الغرض             | قياس أداء البطاقة لصاحبها                                                            |
| الأساس القانوني   | المصلحة المشروعة في قياس أداء محتوى نشره صاحبه للعامة                                |
| البيانات          | **تجزئة زائر يومية** لا رجعة فيها، نوع الحدث، نطاق المُحيل، نوع الجهاز، اللغة، الوقت |
| ما **لا** يُخزَّن | عنوان IP، User-Agent، أي كوكي أو معرّف دائم، الموقع الجغرافي                         |
| مدة الاحتفاظ      | ٩٠ يوماً للأحداث الخام — التجميعات أعداد مجرّدة تبقى                                 |
| التفصيل           | [analytics/definitions.md](../analytics/definitions.md)                              |

> التجزئة تشمل تاريخ اليوم والـslug، فلا يمكن ربط زيارات الشخص عبر
> الأيام ولا عبر البطاقات. هذا قيد مقصود على المنتج لا نقص في التنفيذ.

### 2.9 سجل الإشعارات

| البند           | التفصيل                                        |
| --------------- | ---------------------------------------------- |
| الغرض           | تتبّع نجاح الإرسال وتشخيص أعطاله               |
| الأساس القانوني | المصلحة المشروعة في تشغيل الخدمة               |
| البيانات        | **تجزئة** عنوان المستلم، القالب، الحالة، الوقت |
| ملاحظة          | العنوان نفسه لا يُخزَّن — تجزئة SHA-256 فقط    |

## 3. المستقبِلون ونقل البيانات خارج السلطنة

| المستقبِل       | الغرض                         | الموقع                               |
| --------------- | ----------------------------- | ------------------------------------ |
| Auth0           | المصادقة وإدارة الهوية        | **الولايات المتحدة** (Tenant الحالي) |
| مزوّد البريد    | إرسال الرسائل                 | يُحدَّد مع قرار الاستضافة            |
| مزوّد الاستضافة | تشغيل التطبيق وقاعدة البيانات | **قرار مفتوح**                       |

> ⚠️ **بند يحتاج قراراً وتقييماً:** Tenant الإنتاج في Auth0 ومنطقة
> الاستضافة يحددان ما إذا كان هناك نقل للبيانات خارج السلطنة، وما
> يترتب عليه من متطلبات. تقييم النقل يجب أن يسبق الإطلاق التجاري لا
> أن يليه.

## 5. فجوات معروفة

هذه بنود ناقصة، مذكورة صراحةً لا مسكوت عنها:

1. **تغيير البريد الإلكتروني** — مستثنى من حق التصحيح لأنه يحتاج تدفق
   إعادة تحقق، وقبوله بلا تحقق ناقلُ استيلاء على الحساب. يتم عبر الدعم
   حالياً — راجع [rectification.md](rectification.md).
2. **سياسة الاحتفاظ** — مطبَّقة لأحداث التحليلات الخام (٩٠ يوماً) وحدها.
   لا حذف تلقائي لسجلات التدقيق ولا الإشعارات ولا جهات الاتصال المحذوفة
   حذفاً ناعماً. يجب تحديد المدد واعتمادها ثم أتمتتها.
3. **الإبلاغ عن الاختراق** — لا إجراء موثّق ولا مسؤول محدد.
4. **تقييم نقل البيانات خارج السلطنة** — معلّق على قرار الاستضافة.
5. **سياسة الخصوصية وشروط الاستخدام** — مسوّدتان تحتاجان صياغة
   ومراجعة قانونية.
6. **اتفاقيات معالجة البيانات** مع المؤسسات العميلة — غير موجودة. صارت
   ألزم بعد المرحلة 3: المنصة تحتفظ الآن ببيانات أطراف ثالثة نيابةً عن
   المؤسسات، وهذه بالضبط العلاقة التي تنظّمها الاتفاقية.
7. **مسار طلبات أصحاب بيانات جهات الاتصال** — لا واجهة تمكّن المؤسسة من
   تنفيذ طلب محو أو تصحيح يصلها من شخص في قائمة جهات اتصالها. الحذف
   الناعم موجود، والحذف الصلب يحتاج تدخلاً يدوياً حالياً.
