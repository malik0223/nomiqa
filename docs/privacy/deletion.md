# حذف الحساب — ما يُحذف وما يبقى ولماذا

**آخر تحديث:** 14 أغسطس 2026

هذه الوثيقة تصف السلوك الفعلي المنفَّذ في الشيفرة. أي تغيير في منطق
الحذف يستوجب تحديثها في نفس الـPull Request.

---

## المسار

```
POST /api/v1/me/account/deletion
        │
        ├─ رفض مبكر إن كان إعداد Auth0 Management ناقصاً
        │
        ├─ في معاملة واحدة:
        │     • إنشاء DataSubjectRequest بحالة pending
        │     • وسم المستخدم deletedAt  ← يمنع الدخول فوراً
        │     • إلغاء كل العضويات        ← يمنع الوصول فوراً
        │
        └─ إدراج مهمة في طابور account-deletion
                │
                ▼
        الـWorker (تسلسلي، 5 محاولات، backoff أسّي)
                │
                ├─ 1. حذف ملفات المؤسسات الشخصية من التخزين
                ├─ 2. حذف الهوية من Auth0
                └─ 3. حذف صفوف قاعدة البيانات
                        │
                        └─ تحديث الطلب إلى completed
```

---

## لماذا هذا الترتيب

**الملفات أولاً.** حذفها يحتاج مفاتيحها من قاعدة البيانات. حذف الصفوف
قبلها يفقدنا القدرة على العثور عليها، فتبقى صور شخصية ومستندات في
التخزين إلى الأبد — وهو إخلال بطلب الحذف لا مجرد إهدار مساحة.

**Auth0 قبل صفوفنا.** لو فشل الحذف عندنا بعد حذف الهوية، تكون الهوية
قد انتهت فلا يستطيع الدخول. العكس أسوأ: تختفي بياناتنا وتبقى هويته
قائمة، فيدخل من جديد وتُنشأ له مؤسسة جديدة وكأن الحذف لم يحدث.

**كل خطوة Idempotent.** إعادة المحاولة بعد نجاح جزئي لا تفشل: حذف ملف
غير موجود يُعتبر نجاحاً، و404 من Auth0 يُعتبر نجاحاً.

## ما يُحذف

| البيانات                                  | الآلية                 |
| ----------------------------------------- | ---------------------- |
| صف المستخدم                               | حذف فعلي               |
| العضويات وأدوارها                         | Cascade من المستخدم    |
| الموافقات                                 | Cascade من المستخدم    |
| **المؤسسات الشخصية** التي هو عضوها الوحيد | حذف فعلي مع بياناتها   |
| ملفات تلك المؤسسات                        | حذف من Object Storage  |
| الهوية في Auth0                           | حذف عبر Management API |

## ما يبقى ولماذا

| البيانات                                        | لماذا تبقى                                                                                                            |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **سجل التدقيق**                                 | أثر تشغيلي وأمني. يُصفَّر حقل الفاعل (`SetNull`) فيبقى السجل بلا هوية                                                 |
| **مؤسسات الأعمال** التي يشاركه فيها أعضاء آخرون | بيانات بقية الأعضاء ليست ملكه. تُلغى عضويته فقط                                                                       |
| **DataSubjectRequest**                          | إثبات تنفيذ الطلب. لا مفتاح أجنبي إلى `users` عمداً حتى يبقى بعد الحذف، ولا يحمل بيانات شخصية — معرّف وتجزئة بريد فقط |
| **سجل الإشعارات**                               | لا يحمل عنواناً أصلاً، تجزئة فقط                                                                                      |

## قيد معروف: نقل ملكية مؤسسة الأعمال

إذا كان المستخدم **المالك الوحيد** لمؤسسة تضم أعضاء آخرين، فالحذف
الحالي يلغي عضويته ويترك المؤسسة **بلا مالك**.

هذا قيد مقصود في هذه المرحلة: نقل الملكية يحتاج واجهة اختيار مالك
جديد وسير موافقة، وهو ضمن المرحلة 4 (الشركات والاشتراكات). حتى ذلك
الحين يجب على الدعم التدخل يدوياً في هذه الحالة.

**لا يجوز إطلاق باقات الفرق قبل معالجة هذه الحالة.**

---

## متطلبات التشغيل

حذف الحساب يتطلب تطبيق Machine-to-Machine في Auth0 بصلاحيتي
`read:users` و`delete:users` — راجع
[docs/auth0-setup.md](../auth0-setup.md) القسم 4.

بدونه يُرفض الطلب بـ`503` ورسالة واضحة، ولا يبدأ حذف جزئي. الرفض
المبكر مقصود: بدء الحذف ثم اكتشاف عجزنا عن إتمامه يترك المستخدم في
حالة أسوأ من عدم البدء.

---

## عند الفشل النهائي

بعد استنفاد المحاولات الخمس يُسجَّل الطلب `failed` مع سبب الفشل،
ويُكتب في السجل تحذير يطلب **مراجعة يدوية** — لأن الحساب قد يكون
حُذف جزئياً عبر أنظمة متعددة، وهي حالة لا تُترك للأتمتة.
